# Contributing a skill

Skills are plain repository content. Add or update one in a pull request; the registry index is regenerated by CI and existing CLI versions see the new skill without a release.

## Create a skill

1. Create `skills/<name>/` using a lowercase hyphenated name.
2. Add `SKILL.md` with only the standard frontmatter fields:

   ```markdown
   ---
   name: my-skill
   description: Do a useful thing. Use when the user asks for that thing.
   ---
   ```

3. Add `skill.json` with the same `name` and exact `description`, a SemVer `version`, up to eight lowercase keywords, and a license.
4. Keep the body focused on capability, workflow, constraints, and examples. Do not add registry-specific frontmatter fields.
5. Add only UTF-8 text files. Do not include binaries, symlinks, secrets, generated dependencies, or executable setup steps.

A skill may contain at most 20 files, 512 KiB per file, and 2 MiB total. Paths must remain relative to the skill directory.

## Validate locally

```sh
npm install
npm run typecheck
npm test
npm run validate
```

To regenerate the checked-in index locally:

```sh
npm run build:registry
```

The post-merge registry workflow regenerates `registry.json` with the source commit SHA and commits it to `main`. Contributors do not need to run `npm run build:registry` or include `registry.json` changes in a pull request. The command is available for local validation and authoring, but CI is the source of truth. Do not hand-edit the generated index.

## Review checklist

- The description states both what the skill does and when to use it.
- `SKILL.md` and `skill.json` names and descriptions are identical.
- The skill does not ask an agent to reveal secrets, bypass security, or execute untrusted installation steps.
- Instructions are concise and useful across supported hosts.
- Tests and documentation are updated when behavior changes.
