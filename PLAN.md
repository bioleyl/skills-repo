# skills-repo — Implementation Plan

> A lightweight "npm for AI agent skills": a CLI published on npm, and a skill
> registry that lives as plain data in this same GitHub repository. Skills are
> added or updated with a simple PR — **no CLI release required**.

---

## 1. Overview

**Package:** `@bioleyl/skills-repo` on npm · **Binary:** `skills-repo` (single bin, so
`npx @bioleyl/skills-repo …` works) · **Language:** TypeScript (strict, ESM, Node ≥ 20)

The repository plays two roles:

1. **Code** — the CLI (`src/`, `dist/` shipped to npm).
2. **Data** — the skill registry (`skills/`, never shipped to npm), fetched at
   runtime over GitHub's public endpoints.

A third artifact, **`AGENT.md`** at the repo root, is a self-contained set of
instructions that a coding agent (Claude Code, Codex, Cursor, …) can read to
install skills in the correct location for its host — with or without the CLI.

```text
┌──────────────┐   npx @bioleyl/skills-repo add X    ┌─────────────────────────┐
│   Consumer   │ ────────────────────────────▶ │  CLI (npm, dist/ only)  │
│  dev machine │                               └───────────┬─────────────┘
│              │                                           │ fetch (runtime)
│ .agents/     │◀──────── install files ───────────────────┤
│ .claude/     │                               ┌───────────▼─────────────┐
│ .cursor/ ... │                               │  GitHub repo (data)     │
└──────────────┘                               │  skills/<name>/SKILL.md │
                                               │  registry.json (index)  │
      ┌──────────────┐   "read AGENT.md and    │  AGENT.md (manual mode) │
      │ Coding agent │──install skills────────▶└─────────────────────────┘
      └──────────────┘    without the CLI"
```

### Goals

- `npx @bioleyl/skills-repo add <skill>` installs a skill into the right directories
  for the agents present on the machine.
- Skills are pure repo content: adding/updating one is a git push, instantly
  available to every existing CLI installation.
- Strong typing, clean layering, pure domain logic, effectful edges.
- Works offline-ish (cache), reproducibly (commit pinning), cross-platform.

### Non-goals (v1)

- Skill dependency resolution between skills (v2 candidate).
- Publishing/authoring workflow beyond a PR (no `npx @bioleyl/skills-repo publish`).
- Private registries beyond a public GitHub repo (`--registry` flag allows
  pointing at another public repo; auth only via `GITHUB_TOKEN` for rate limits).
- Executing or validating skill *scripts* at install time — skills are
  untrusted content; the CLI never runs anything it installs.

## 2. Core concepts

| Term | Meaning |
|---|---|
| **Skill** | A directory `skills/<name>/` containing `SKILL.md` (entrypoint, Anthropic Agent Skills format), `skill.json` (registry manifest), and optional `scripts/`, `references/`, `assets/` subdirectories. |
| **Skill doc** | The parsed + validated frontmatter of a `SKILL.md` (`name`, `description`) — the part agent loaders read. |
| **Skill manifest** | `skill.json` in the skill folder — the npm-style registry manifest (version, keywords, author, compatibility). |
| **Registry index** | `registry.json` at repo root, generated by CI: the list of all skills with metadata + the commit SHA it was generated from. |
| **Registry source** | A GitHub repo coordinates triple `owner/repo@ref` (default: this repo, `@main`). |
| **Install target** | An `(agent, scope, path)` triple — e.g. `(claude-code, project, .claude/skills/<name>)`. |
| **Lockfile** | `skills.lock.json` (project) / `~/.config/skills-repo/lock.json` (user): what is installed, from where, at which SHA, into which targets. Enables `remove`, `update`, and reproducibility. |

### Skill format — two files, two audiences

Each skill folder contains two files with distinct roles:

- **`SKILL.md` — for agents.** Exactly the cross-agent Agent Skills format
  (Claude Code, Codex, Cursor, Windsurf all read it natively): minimal
  frontmatter (`name`, `description`) + markdown body. No registry-specific
  fields, so it stays 100 % loader-compatible.
- **`skill.json` — for the registry.** The npm-style manifest: version,
  keywords, author, compatibility, license. Familiar to author, robust to
  parse (zod), free to evolve without touching the agent-facing standard.

```yaml
# skills/pdf-report/SKILL.md
---
name: pdf-report            # required. ^[a-z0-9]+(-[a-z0-9]+)*$, must equal dir name
description: >              # required. ≤ 1024 chars. What it does + when to use it.
  Generate branded PDF reports from markdown. Use when the user asks to
  export a document as PDF.
---
Markdown body: instructions, workflows, examples…
```

```jsonc
// skills/pdf-report/skill.json
{
  "name": "pdf-report",               // must equal dir name AND SKILL.md name
  "version": "1.2.0",                 // SemVer, required
  "description": "Generate branded PDF reports from markdown.",
                                      // must equal SKILL.md description
  "keywords": ["pdf", "reporting"],   // ≤ 8, lowercase
  "author": "leal",
  "license": "MIT",
  "compatibility": ["claude-code", "codex", "cursor", "windsurf"]   // omit → all
}
```

`name`/`description` necessarily appear in both files (the standard requires
them in `SKILL.md`; the registry needs them searchable in JSON). CI enforces
equality, so the duplication can never drift.

Validation rules (enforced by CI on every PR and by the CLI before install):

- `name` matches the directory name and the slug regex, in both files.
- `description` non-empty, ≤ 1024 chars, identical in both files.
- `skill.json` parses against the zod schema; `version` is valid SemVer.
- Files are UTF-8 text only (no binaries); no symlinks; no file > 512 KB;
  skill total ≤ 2 MB; max 20 files.
- No path escapes (`..`) — file paths are relative, forward-slash, within the
  skill folder.

## 3. Repository layout

```text
skills-repo/
├── skills/                     # THE REGISTRY (data, not shipped to npm)
│   ├── commit-lint/
│   │   ├── SKILL.md            # agent-facing (standard format)
│   │   └── skill.json          # registry manifest (npm-style)
│   └── pdf-report/
│       ├── SKILL.md
│       ├── skill.json
│       └── references/layout.md
├── registry.json               # CI-generated index (checked in, never hand-edited)
├── AGENT.md                    # agent-facing install instructions (see §7)
├── PLAN.md                     # this file
├── README.md
├── CONTRIBUTING.md             # how to add a skill (PR flow)
├── site/                       # generated static catalog for GitHub Pages
├── package.json                # bin: skills-repo; files: ["dist"]  ← skills excluded
├── tsconfig.json
├── .github/workflows/
│   ├── ci.yml                  # typecheck, lint, test, build
│   ├── registry.yml            # regenerate registry.json on skills/ changes
│   ├── pages.yml               # deploy the static skill catalog
│   └── release.yml             # npm publish on vX.Y.Z tags
├── src/                        # the CLI (§6)
└── tests/
    ├── fixtures/registry/      # a miniature local registry for tests
    └── e2e/
```

`registry.json` schema (single source for `search`, `list --available`, `info`):

```jsonc
{
  "version": 1,                       // index format version
  "generatedAt": "2025-09-04T12:00:00Z",
  "commitSha": "9f2c1ab…",            // the SHA the index was built from
  "skills": [
    {
      "name": "pdf-report",
      "description": "Generate branded PDF reports…",
      "version": "1.2.0",
      "keywords": ["pdf", "reporting"],
      "path": "skills/pdf-report",
      "files": ["SKILL.md", "skill.json", "references/layout.md"],
      "sizeBytes": 18234
    }
  ]
}
```

The `files` array is the exact file list per skill — it drives both the CLI
fetch (§4) and AGENT.md manual installs (§7), so no git-tree listing or
tarball unpacking is ever needed.

### Starter skill catalog (shipped in Phase 5)

Seven genuinely useful, self-contained skills to launch the registry — each is

|---|---|---|
| `commit-lint` | Write Conventional Commits messages. Use for every git commit. | git, commits |
| `pr-reviewer` | Structured code review — correctness, security, performance, tests — with severity-tagged findings. Use when reviewing a PR or code. | review, quality |

| `changelog-keeper` | Maintain CHANGELOG.md (Keep a Changelog format) and derive the SemVer bump from commits. Use when preparing a release. | changelog, release, semver |
| `refactor-plan` | Plan safe, incremental refactorings: characterize behavior first, small reversible steps, tests stay green. Use when refactoring. | refactoring, tech-debt |
| `skill-creator` | Author skills for this registry: SKILL.md structure, description quality (capability + trigger), skill.json manifest, lean bodies. Use when creating or improving a skill. | skills, authoring |

## 4. Remote access strategy (GitHub as backend)

All reads go through a small `RegistryClient` port. **No git client, no
tarballs — only plain HTTPS `GET`s of small files.**

| Operation | Strategy | Notes |
|---|---|---|
| `getIndex(source)` | `GET https://raw.githubusercontent.com/<owner>/<repo>/<ref>/registry.json` | One request. Cached (TTL 5 min, `--no-cache` to bypass). |
| `fetchSkillFiles(source, sha, files)` | Parallel `GET https://raw.githubusercontent.com/<owner>/<repo>/<sha>/<file>` for each path in the skill's `files` list | Skills are small (≤ 20 files, ≤ 512 KB each, ≤ 2 MB total) — per-file raw fetches with a small concurrency cap (≈ 6) are cheap and simple. |

- **Pinning:** the index carries `commitSha`. `add` fetches files at that SHA
  and records it in the lockfile → reproducible installs. A SHA-pinned raw URL
  is immutable, so its cache entry never invalidates.
- Refresh/repair path (index stale, or a skill missing from it):
  `GET https://api.github.com/repos/<owner>/<repo>/git/trees/<ref>?recursive=1`
  — one request listing every file; used by `update` and dev tooling, never on
  the `add` happy path. This is the only `api.github.com` call (rate-limited;
  `GITHUB_TOKEN` honored when present).
- Dev/test escape hatch: `--registry file://<path>` maps the port to a local
  directory (same code paths, zero network) — used by tests and local authoring.

### Agent install targets

Verified conventions (re-verify in Phase 0 with a smoke test per agent):

| Agent id | Project scope | User (global) scope |
|---|---|---|
| `portable` (default base) | `.agents/skills/<name>/` | `~/.agents/skills/<name>/` |
| `claude-code` | `.claude/skills/<name>/` | `~/.claude/skills/<name>/` |
| `codex` | `.codex/skills/<name>/` (also reads `.agents/skills/`) | `~/.codex/skills/<name>/` |
| `cursor` | `.cursor/skills/<name>/` (also reads `.agents/skills/`) | `~/.cursor/skills/<name>/` |
| `windsurf` | `.windsurf/skills/<name>/` (also reads `.agents/skills/`) | `~/.codeium/windsurf/skills/<name>/` |

**Default install policy (pure, testable rule):** write once into the portable
target (`.agents/skills/`), and *additionally* copy into `.claude/skills/` when
Claude Code is detected (it does not read `.agents/`). `--agent <ids>` opts into
native dirs for any agent; `--scope project|user` selects the scope (default:
project). The rule lives in `core/targets.ts` as a pure function of
`(detectedAgents, flags, os)`.

### Lockfile

`skills.lock.json` (project root). User-scope installs are tracked in
`~/.config/skills-repo/lock.json` instead (XDG-aware).

```jsonc
{
  "version": 1,
  "registry": { "ownerRepo": "bioleyl/skills-repo", "ref": "main" },
  "skills": [
    {
      "name": "pdf-report",
      "version": "1.2.0",
      "commitSha": "9f2c1ab…",
      "installedAt": "2025-09-04T12:01:00Z",
      "scope": "project",
      "targets": [
        { "agent": "portable", "path": ".agents/skills/pdf-report" },
        { "agent": "claude-code", "path": ".claude/skills/pdf-report" }
      ]
    }
  ]
}
```

Invariants: every target path in the lockfile is derived (never free-form
input) by `core/planInstall.ts`; `remove` and `update` only touch paths that
appear in the lockfile.

## 5. CLI surface

Binary `skills-repo` (package `@bioleyl/skills-repo`; single bin ⇒ `npx @bioleyl/skills-repo …`
works). Style: quiet success, actionable errors, no stack traces for expected
failures, JSON output via `--json` for every command (agent-friendliness).

| Command | Args/Flags | Behavior |
|---|---|---|
| `init` | `--scope`, `--agent <ids>`, `--yes` | Detect agents, create `skills.lock.json`, print the plan it will use for future `add`s. |
| `add <skill…>` | `--agent`, `--scope`, `--registry`, `--force`, `--yes`, `--no-cache` | Resolve in index → fetch files at pinned SHA → validate `SKILL.md` + `skill.json` → compute install plan → write files → update lockfile. Refuses to overwrite unless `--force`. |
| `remove <skill…>` | `--yes` | Delete lockfile-tracked dirs only, prune empty parent dirs, update lockfile. |
| `list` | `--available` | Default: installed skills from lockfile (name, version, agents, up-to-date?). `--available`: all skills in index. |
| `search <query>` | `--keyword`, `--json` | Filter index by fuzzy-ish match on name/description/keywords (pure scoring function). |
| `info <skill>` | | `skill.json` + frontmatter details, install state, up-to-date status. |
| `update [skill…]` | `--all`, `--dry-run` | Diff lockfile vs fresh index; reinstall changed skills at new SHA. `--dry-run` prints the plan only. |
| `agents` | | Detected agents, their skill dirs, and which targets the CLI would use. |
| `validate` | (dev) | Validate all skills in a local checkout — used by CI and skill authors. |

Exit codes: `0` success · `1` expected failure (network, not-found, conflict) ·
`2` usage error. Unexpected exceptions are caught at the CLI boundary, printed
briefly, and reported with `--debug` stack traces.

## 6. TypeScript architecture

**Functional core, imperative shell.** Five layers with a strict one-way
dependency rule, enforced mechanically (ESLint `no-restricted-imports` +
`dependency-cruiser` in CI):

```text
types  ◀──  core  ◀──  app  ◀──  cli  ◀──  index.ts (composition root)
                 ▲
                infra  (implements ports declared in types)
```

```text
src/
├── types/                      # Domain types + PORTS (interfaces). Imports nothing.
│   ├── domain.ts               # Skill, SkillDoc, SkillManifest, RegistryIndex,
│   │                           # AgentId, InstallTarget, InstallPlan, Lockfile, Result<T,E>
│   └── ports.ts                # HttpPort, FsPort, AgentDetectorPort,
│                               # ClockPort, ConsolePort, EnvPort
├── core/                       # PURE. No fs/net/process/console/Date.now/random.
│   ├── skillDoc.ts             # parseSkillMd(text) → Result<SkillDoc, DocError>
│   ├── manifest.ts             # parseSkillJson + doc↔manifest consistency check
│   ├── index.ts                # parseRegistryIndex, searchIndex, findSkill
│   ├── versioning.ts           # semver compare, satisfies, diff detection
│   ├── lockfile.ts             # parse, serialize, applyAdd/applyRemove, diffToIndex
│   ├── planInstall.ts          # (skill, policy, detectedAgents) → InstallPlan
│   ├── targets.ts              # agent→paths matrix, default policy resolution
│   └── schema.ts               # zod schemas for boundary data (SKILL.md frontmatter,
│                               # skill.json, registry.json, lockfile); inferred types re-exported
├── infra/                      # Effectful adapters, each implementing a port.
│   ├── githubClient.ts         # RegistryClient impl: index + parallel raw file fetches
│   ├── fsAdapter.ts            # FsPort impl over node:fs/promises (path-contained)
│   ├── agentDetector.ts        # AgentDetectorPort impl: dir existence + env probing
│   ├── cache.ts                # index TTL cache + immutable SHA-pinned file cache (FsPort-based)
│   └── clockEnv.ts             # Clock/Env impls (injected, never imported by core)
├── app/                        # Use cases; orchestrate core with injected ports.
│   ├── addSkill.ts  removeSkill.ts  searchSkills.ts  listSkills.ts
│   ├── updateSkills.ts  skillInfo.ts  initProject.ts  detectAgents.ts
│   └── context.ts              # AppContext = { registry, fs, detector, clock, console }
├── cli/                        # Thin: parse → call app → render.
│   ├── commands/*.ts           # one file per command, pure option objects
│   ├── render.ts               # human + --json output formatters (pure functions)
│   └── errors.ts               # DomainError → message + exit code mapping (exhaustive)
└── index.ts                    # Composition root: build real infra, inject, wire commander
```

### Purity contract

- **core** functions are pure: same input ⇒ same output, no side effects, all
  non-determinism (time, env, randomness) injected as arguments. They return
  `Result<T, E>` instead of throwing.
- **infra** may perform effects but contains no business rules; every function
  is behind a port so `app` is testable with fakes.
- **app** is the only place that sequences effects; each use case is a small
  function `(ctx, input) → Promise<Result<Output>>`.
- **cli** contains zero logic — argument parsing (commander), one call into
  `app`, rendering, exit-code mapping.

### Key types (sketch)

```ts
// types/domain.ts
export type Result<T, E> =
  | { readonly ok: true; readonly value: T }
  | { readonly ok: false; readonly error: E };

export type SkillName = string & { readonly __brand: "SkillName" }; // validated slug
export type AgentId = "portable" | "claude-code" | "codex" | "cursor" | "windsurf";
export type Scope = "project" | "user";

export interface RegistrySource {
  readonly ownerRepo: `${string}/${string}`;
  readonly ref: string;                       // branch, tag or 40-hex sha
}

export interface SkillDoc {              // SKILL.md frontmatter (the agent standard)
  readonly name: SkillName;
  readonly description: string;
}

export interface SkillManifest {         // skill.json (the registry manifest)
  readonly name: SkillName;
  readonly version: SemVer;
  readonly description: string;
  readonly keywords: readonly string[];
  readonly author?: string;
  readonly license?: string;
  readonly compatibility: readonly AgentId[];   // default: all
}

export interface InstallTarget {
  readonly agent: AgentId;
  readonly scope: Scope;
  readonly path: string;                         // derived, never user input
}

export interface InstallPlan {                   // fully computed BEFORE any write
  readonly skill: SkillManifest;
  readonly source: RegistrySource;
  readonly commitSha: string;
  readonly targets: readonly InstallTarget[];
  readonly operations: readonly FileOperation[]; // {action:"write"|"delete", path, content}
}

// types/ports.ts — the whole outside world, as seen by core/app
export interface RegistryClientPort {
  getIndex(source: RegistrySource): Promise<Result<RegistryIndex, RegistryError>>;
  fetchSkillFiles(source: RegistrySource, sha: string, files: readonly string[]):
    Promise<Result<readonly SkillFile[], RegistryError>>;   // parallel raw GETs
}
export interface HttpPort { get(url: string): Promise<Result<HttpBody, HttpError>> }
export interface FsPort   { /* readFile, writeFile, mkdir, rm, exists — all path-scoped */ }
export interface AgentDetectorPort { detect(): DetectedAgent[] }
export interface ClockPort { now(): Date }
```

### Typing standards

- `tsconfig`: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
  `noImplicitOverride`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`.
- Runtime boundaries (`SKILL.md` frontmatter, `skill.json`, `registry.json`,
  lockfile, CLI options) are parsed with **zod** — parse, don't validate:
  unknown input ⇒ typed output.
- Discriminated unions + `assertNever` for exhaustive error rendering.
- Branded types (`SkillName`, `SemVer`, `Sha1`) constructed only by validated
  smart constructors in `core`.
- All domain types deeply `readonly`; `satisfies` for literal configs.
- Node ≥ 20: use global `fetch`, `node:fs/promises`, `node:path`, ESM only.
  Runtime deps kept minimal: `commander`, `zod`, `@clack/prompts`,
  `picocolors`, `semver`. Everything else is dev dependencies.

## 7. AGENT.md — the agent-facing installer document

A self-contained file at the repo root. It must let an agent install skills
**without the CLI**, and must not depend on CLI internals. Sections:

1. **What this is** — one paragraph: a registry of installable agent skills.
2. **Preferred path** — run `npx @bioleyl/skills-repo add <name>` (then verify the
   lockfile entry); stop here if it succeeded.
3. **Install locations** — the matrix from §4, verbatim, with absolute
   `~`-expanded examples and "pick user vs project scope" rules.
4. **Discovering skills** — fetch `<raw-url>/registry.json`; each entry lists
   name, description, version, keywords, and the exact `files` to install.
5. **Manual install** — the entry's `files` array lists every file. Fetch each
   from `https://raw.githubusercontent.com/<owner>/<repo>/<sha>/skills/<name>/<file>`
   into the chosen target directory (preserve structure, `SKILL.md` at the
   folder root, keep `skill.json` — agents ignore it, the CLI uses it for
   `update`/`remove` bookkeeping).
6. **Rules** — never execute anything while installing; don't edit skill
   content; `name` frontmatter = folder name; if the agent's host isn't in the
   compatibility list, warn the user first.
7. **Contributing a skill** — pointer to CONTRIBUTING.md.

URLs in AGENT.md are absolute (owner filled in once, in one place). CI checks
that AGENT.md's matrix matches `core/targets.ts` (single source of truth: the
matrix is generated into a table snippet by a dev script).

## 8. Error handling & exit codes

- Every failure a user can hit is a **value**: `ManifestError |
  RegistryError | ConflictError | LockfileError | NetworkError` — each carrying
  structured context (skill name, path, HTTP status…), mapped exhaustively to a
  human message + exit code in `cli/errors.ts`.
- Unexpected exceptions: caught once at the CLI boundary; `1` + short message;
  full stack only with `--debug`; a `--json` run emits a structured error.
- No retries in v1 except one idempotent retry on the index fetch.

## 9. Security

- Skills are **untrusted content**: install = file writes only; the CLI never
  evaluates or executes anything from a skill.
- Fetched file paths are taken from the index's `files` list (never free-form
  user input), validated against slug/relative-path rules, and size-capped;
  the write step refuses any path outside the computed target directory.
- Lockfile/registry are parsed with zod (no `JSON.parse` + hope).
- `GITHUB_TOKEN` only read from env, never written to disk or logs.
- Prompt-injection note in README: skills instruct the agent that reads them —
  users should review `description` before installing (shown before `add`
  unless `--yes`).

## 10. Testing

- **Unit (vitest)** — `core/*` exhaustively: skillDoc parsing (valid/invalid
  frontmatter), skill.json parsing + doc↔manifest consistency, index search,
  version diff, lockfile transitions, install planning (all agent/scope
  combinations). No mocks needed: pure functions + injected fakes.
- **Contract tests** — each port has a fake (in `tests/fakes/`) and infra
  implementations are tested against the same contract suite; `file://` registry
  fixture exercises the GitHub client paths minus network.
- **Integration/e2e** — real `app` + fake ports against
  `tests/fixtures/registry/`: add → list → update (bump fixture version) →
  remove; assert the exact file tree and lockfile. One live smoke test
  (optional, `SKIP_LIVE=1`) against the real GitHub repo after it exists.
- **Mutation-resistant style**: test behaviors and error values, not messages.
- Coverage gate: 100% branches on `core/`, ≥ 85% overall (Codecov, non-blocking
  at first, blocking before v1).

## 11. CI/CD (GitHub Actions)

| Workflow | Trigger | Does |
|---|---|---|
| `ci.yml` | PR, push | `pnpm typecheck && lint && test && build` + `depcruise` layer check |
| `registry.yml` | push to `main` touching `skills/**` or `AGENT.md` | Run `skills-repo validate` (dogfood), regenerate `registry.json` via `scripts/build-registry.ts` (reuses the same `core` parsers), commit it back — this is what makes new skills instantly live |
| `release.yml` | manual `workflow_dispatch` | Run verification, build, and `npm publish` (`files: ["dist", "README.md"]` — no `skills/`) using the selected dist-tag |

`registry.json` is committed (not an artifact) so raw.githubusercontent.com can
serve it — CI is the only writer; a CODEOWNERS + CI check rejects manual edits.

## 12. Implementation phases

Each phase ends green (build + tests + lint) before the next starts.

**Phase 0 — Foundations (~0.5 day)**
Scaffold: `package.json` (bin, engines, files), tsconfig with all strict flags,
eslint + prettier + dependency-cruiser layer rules, vitest, GitHub repo owner
confirmed. *AC: `pnpm i && pnpm test && pnpm build` pass on an empty skeleton.*

**Phase 1 — Pure core (~1.5 days)**
`types/domain.ts`, `types/ports.ts`, `core/*` with full unit tests (skillDoc,
manifest + consistency, schema, index, versioning, lockfile, targets,
planInstall). *AC: 100% branch coverage in `core/`; dependency-cruiser proves
zero infra imports; all invalid-fixture cases return typed errors, never throw.*

**Phase 2 — Infra (~1 day)**
`githubClient` (parallel raw fetches from the index file list + trees refresh
path + `file://`), `fsAdapter`, `agentDetector`, `cache`. *AC: contract suite
green for every port impl; client rejects path-escape/oversized fixtures.*
