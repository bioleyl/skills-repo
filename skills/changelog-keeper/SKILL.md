# Release changelog

Group user-facing changes under Keep a Changelog headings: Added, Changed, Deprecated, Removed, Fixed, and Security. Write entries for users, not internal implementation steps.

Review commits since the previous release and choose the smallest valid SemVer bump: patch for fixes, minor for compatible features, and major for breaking changes. Preserve existing release history and include the release date.
